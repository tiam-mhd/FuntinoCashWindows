# فانتینو | مرکز کنترل — نسخه‌ی بازطراحی‌شده

این پوشه شامل سورس یک برنامه‌ی Windows Forms با هدف مدیریت و گزارش‌گیری از دو پایگاه داده‌ی مرجع شهربازی است. پروژه برای .NET Framework 4.8 و هدف پردازشی x86 تنظیم شده تا با ویندوز ۷ SP1 به بعد و SDKهای قدیمی‌تر POS سازگاری بیشتری داشته باشد.

## چه چیزی داخل برنامه است؟

- ورود امن با حساب اولیه‌ی `Admin`؛ گذرواژه‌ی تصادفی و یک‌بارمصرف در اولین راه‌اندازی ساخته و فقط همان موقع نمایش داده می‌شود. در اولین ورود، تغییر گذرواژه اجباری است.
- هش گذرواژه با PBKDF2 و salt تصادفی ذخیره می‌شود؛ متن گذرواژه در دیتابیس ذخیره نمی‌شود.
- داشبورد، فهرست و مرور جدول‌ها در هر دو پایگاه `SharjReportDB0216_New` و `DBKart_New`.
- جست‌وجوی متنی روی ستون‌ها، صفحه‌بندی، افزودن، ویرایش، حذف، تازه‌سازی و ثبت تغییرات در تراکنش SQL.
- جلوگیری از ویرایش/حذف جدول فاقد کلید اصلی و پشتیبانی از تشخیص تغییر هم‌زمان برای جدول‌هایی که rowversion دارند.
- خروجی Excel با فرمت XLSX و گزارش PDF بصری با متن فارسی و صفحه‌بندی.
- تنظیم نمونه‌ی SQL Server، احراز هویت ویندوزی یا SQL، COM کارت‌خوان و POS و نرخ baud.
- آزمون بازشدن پورت سریال و آزمون SDK موجود `SSP1126.PcPos.dll`؛ رخدادهای عیب‌یابی در `DBKart_New` ثبت می‌شوند.
- مهاجرت‌های افزایشی و تکرارپذیر هنگام شروع برنامه؛ جداول اختصاصی برنامه با پیشوند `App` ساخته می‌شوند و جداول مرجع تغییر نمی‌کنند.
- طراحی کنترل‌ها و چیدمان فرم‌ها در فایل‌های `*.Designer.cs` است. کد فرم‌ها فقط منطق رویداد و اتصال داده را نگه می‌دارد.

## راه‌اندازی روی ویندوز

1. ZIP را در مسیر دلخواهی مثل `C:\FuntinoControlCenter` استخراج کنید.
2. پوشه‌ی `Databases` چهار فایل MDF/LDF دارد. با SQL Server Management Studio فایل `Build\Attach-Databases.sql` را باز کنید، مسیر داخل اسکریپت را با مسیر استخراج واقعی جایگزین کنید و دیتابیس‌ها را با نام‌های دقیق `SharjReportDB0216_New` و `DBKart_New` Attach کنید. سرویس SQL Server نیز باید اجازه‌ی خواندن این پوشه را داشته باشد. اگر می‌خواهید دستی Attach کنید، همین دو نام را برای Catalog انتخاب کنید.
3. با حساب ویندوزی‌ای اجرا کنید که دسترسی خواندن و نوشتن به هر دو دیتابیس Attach‌شده دارد. اگر SQL Authentication لازم است، در صفحه‌ی تنظیمات برنامه آن را انتخاب کنید.
4. پروژه را از `FuntinoControlCenter.sln` در Visual Studio باز کنید و **.NET Framework 4.8 Developer Pack** را نصب داشته باشید. یا `Build\Build-Windows.cmd` را اجرا کنید. فایل خروجی در `bin\Release\FuntinoControlCenter.exe` ساخته می‌شود.
5. برنامه را اجرا کنید. در اولین اجرا، migrationهای افزایشی اجرا و حساب اولیه ساخته می‌شود؛ گذرواژه‌ی تصادفی در پنجره‌ای نمایش داده می‌شود. سپس با `Admin` و همان گذرواژه وارد شوید و گذرواژه‌ی خودتان را تنظیم کنید.

> فایل‌های MDF/LDF در پوشه‌ی `Databases` پروژه می‌مانند و به خروجی `bin` کپی نمی‌شوند؛ چون SQL Server هنگام Attach فایل‌ها را قفل می‌کند و کپی آن‌ها بیلد را می‌شکند. برنامه به فایل‌های داخل `bin` وابسته نیست و فقط به کاتالوگ‌های Attach‌شده‌ی `_New` وصل می‌شود. دیتابیس‌ها را از همان پوشه‌ی `Databases` و با اسکریپت بالا Attach کنید.

## اتصال و پورت‌ها

نام نمونه‌ی SQL Server در اولین اجرا خالی است؛ آن را در صفحه‌ی تنظیمات وارد کنید. نام پیش‌فرض پورت‌ها `COM11` برای کارت‌خوان و `COM21` برای POS است. فایل `controlcenter.settings` در کنار برنامه قرار می‌گیرد؛ گذرواژه‌ی SQL در آن با DPAPI ویندوز و برای همان حساب کاربری رمز می‌شود.

## مرزهای عملیاتی و نیازهای تأیید

- برنامه‌ی اصلی مرجع فقط به‌صورت EXE و DLL ارائه شده و سورس C# آن در بسته‌ی ورودی نبود. بنابراین این پروژه «بازسازی کاملِ رفتار اختصاصی فروش/شارژ و پرداخت» محسوب نمی‌شود؛ فعلاً عملیات امن مدیریت داده، مرور، گزارش و آزمون اتصال دستگاه‌ها را فراهم می‌کند.
- فرم مرور جدول اجازه‌ی ویرایش مستقیم جداول تجاری را برای Admin می‌دهد. این قابلیت برای مدیریت/اصلاح داده است و جایگزین گردش‌کار فروش، شارژ کارت، استرداد وجه، محاسبه‌ی تخفیف، صندوق و منطق Stored Procedureهای مرجع نیست. قبل از استفاده‌ی عملیاتی، گردش‌کارها باید با اسکیما و Stored Procedureها در SQL Server مقصد تطبیق داده شوند.
- آزمون COM فقط باز و بسته شدن پورت در سیستم‌عامل را می‌سنجد. اجرای متد `ConnectionTest` در SDK فقط وقتی انجام می‌شود که نسخه‌ی DLL همان متد بدون پارامتر را ارائه کند. هیچ تراکنش مالی یا شارژ واقعی از این صفحه انجام نمی‌شود.
- به‌دلیل نبود SQL Server ویندوزی و سخت‌افزار کارت‌خوان/POS در محیط ساخت، سورس و بسته‌بندی بررسی شده‌اند اما EXE کامپایل‌شده و آزمون سخت‌افزاری در این محیط قابل تولید/تأیید نبود. فایل ساخت ویندوز داخل `Build` قرار دارد؛ برای تحویل EXE واقعی باید آن را در ویندوز با .NET Framework 4.8 Developer Pack بسازید.

## ساختار پوشه

| مسیر | محتوا |
|---|---|
| `Forms\*.Designer.cs` | طراحی کامل فرم‌ها و کنترل‌ها |
| `Database` | اتصال محدود به Catalogهای `_New`، migration، مرور و CRUD امن |
| `Security` | هش PBKDF2 گذرواژه |
| `Services` | گزارش PDF/XLSX، عیب‌یابی سخت‌افزار و ثبت رویداد |
| `Databases` | نسخه‌ی کپی‌شده‌ی دو دیتابیس تجاری مرجع با نام `_New` |
| `Assets` | تصاویر پس‌زمینه‌ی تولیدشده برای صفحه ورود و گزارش |
| `External` | DLL موجود POS از بسته‌ی مرجع |
