# فانتینو | مرکز کنترل ویندوز

این مخزن سورس برنامه‌ی Windows Forms و فرایند ساخت نصب‌گرهای آفلاین آن را نگه می‌دارد.

## ساخت برنامه

- برنامه با .NET Framework 4.6.1 و هدف x86 ساخته می‌شود.
- نسخه‌ی محصول فقط در `Build/Version.props` نگهداری می‌شود.
- برای ساخت ZIP توسعه‌ای، Visual Studio یا Build Tools با .NET Framework 4.6.1 Developer Pack و فایل `Build/Build-Windows.cmd` را اجرا کنید.

## ساخت نصب‌گرها

فهرست رسانه‌های لازم، مسیرها و جدول تقسیم پیش‌نیازها در `Build/Prerequisites.md` آمده است. پس از آماده‌کردن آن‌ها و نصب Inno Setup 6، در PowerShell اجرا کنید:

```powershell
Set-Location FuntinoControlCenter\Build
./Build-Installer.ps1
```

اسکریپت شش خروجی جدا می‌سازد: Windows 7 x86 و x64، Windows 8 x64، Windows 8.1 x64، Windows 10 x64 و Windows 11 x64. هر بسته فقط رسانه‌های لازم برای همان سیستم را دارد. به همین دلیل KB2919355 حجیم فقط در بسته‌ی Windows 8.1 قرار می‌گیرد و پیش‌نیازهای Windows 7 هم بر اساس معماری جدا هستند.

نصب‌گرها و manifest هش SHA-256 در `Build/Output` ساخته می‌شوند. نسخه در `Build/Version.props` تنظیم می‌شود. فایل‌های پیش‌نیاز و خروجی در Git نادیده گرفته شده‌اند.

## سازگاری سیستم‌ها

| ویندوز مقصد | معماری | SQL Server Express |
|---|---|---|
| Windows 7 SP1 | x86 و x64؛ نصب‌گر جدا | 2014 SP3 |
| Windows 8 | فقط x64 | 2017 |
| Windows 8.1 | فقط x64 | 2017 |
| Windows 10 | فقط x64 | 2019 |
| Windows 11 | فقط x64 | 2019 |

روی Windows 7، نصب‌گر پیش‌نیازهای سرویس‌دهی و SHA-2 متناسب با معماری را نصب می‌کند و قابلیت .NET Framework 3.5 ویندوز را فعال می‌کند. روی Windows 8.1، KB2919442 و سپس KB2919355 اعمال می‌شوند. اگر نصب پیش‌نیازی Restart بخواهد، پس از راه‌اندازی مجدد همان نصب‌گر را اجرا کنید.

نام Instance در همه‌ی سیستم‌ها `FuntinoSqlServer` است. نام پیش‌فرض دو پایگاه عملیاتی `FuntinoParkOperations` و `FuntinoDeviceOperations` است و در کلیدهای `MainDatabaseCatalog` و `DeviceDatabaseCatalog` فایل `App.config` تنظیم می‌شود. نصب‌گر اگر پایگاهی با این نام موجود باشد، همان پایگاه و فایل‌هایش را حفظ می‌کند؛ اگر وجود نداشته باشد، یک کپی خصوصی از MDF/LDF مرجع را با همین نام Attach می‌کند. پایگاه موجود rename یا بازنویسی نمی‌شود و برنامه پایگاه‌هایی با پسوند `New` نمی‌سازد. فایل‌های مرجع اصلی در زمان اجرای برنامه باز نمی‌شوند. در اولین اجرای برنامه، migrationهای افزایشی روی هر پایگاه عملیاتی و در تراکنش جداگانه اجرا و نسخه‌شان ثبت می‌شود.

پیش از نصب نسخه‌ی تازه، از `FuntinoParkOperations` و `FuntinoDeviceOperations` نسخه‌ی پشتیبان SQL بگیرید. برای بازیابی، برنامه و کار همگام‌سازی را ببندید و هر پایگاه را از نسخه‌ی پشتیبان خودش با همان نام بازگردانید؛ فایل‌های MDF/LDF مرجع را جایگزین پایگاه عملیاتی نکنید. در پنجره‌ی «تنظیم ارتباط فانتینو»، نشانی HTTPS، شناسه‌های اعتبارنامه/سازمان/شعبه و کلید HMAC را وارد کنید. کلید در تنظیمات همان حساب ویندوز با DPAPI محافظت می‌شود؛ شناسه‌ی پایدار این نصب در دیتابیس ثبت می‌شود و مقدار کلید هرگز در گزارش ثبت نمی‌شود.

نصب‌گر برای حساب ویندوزی انتخاب‌شده، یک وظیفه‌ی زمان‌بندی‌شده‌ی مخفی می‌سازد که هنگام ورود کاربر worker همگام‌سازی را جدا از پنجره‌ی اصلی اجرا می‌کند و پس از توقف ناگهانی آن را دوباره راه می‌اندازد. حذف برنامه ابتدا از worker درخواست توقف کنترل‌شده می‌کند و سپس وظیفه را حذف می‌کند. تا وقتی ارتباط یا نگاشت آماده نیست، عملیات محلی مجاز در صف پایدار می‌ماند و برنامه بدون شبکه باز می‌شود.

جدول‌های داخلی برنامه در schema با نام `app` ساخته می‌شوند. migrationها در این مخزن فقط build شده‌اند؛ نصب یا migration محیط عملیاتی در این کار اجرا نشده است.

## کاربران، نقش‌ها و مجوزها

- در ورود اولیه، گذرواژه‌ی موقت مدیر فقط همان یک بار نمایش داده می‌شود و دکمه‌ی «کپی گذرواژه» دارد. آن را در جای امن نگه دارید. مدیر پس از ورود باید گذرواژه‌ی شخصی تازه‌ای تعیین کند.
- مدیر مجاز از بخش «کاربران و دسترسی‌ها» حساب و نقش می‌سازد. برای حساب تازه یا بازنشانی گذرواژه، برنامه یک گذرواژه‌ی تصادفی و یک‌بارمصرف می‌سازد و فقط همان لحظه در پنجره‌ی قابل‌کپی نشان می‌دهد. کاربر در ورود بعدی ناچار است پیش از دسترسی به بخش‌های دیگر، گذرواژه را عوض کند.
- مجوزها به زبان فارسی و جداگانه برای دیدن، افزودن، ویرایش و حذف داده‌های هر حوزه تعریف شده‌اند؛ مجوزهای گزارش، دستگاه‌ها، تنظیمات و مدیریت حساب‌ها هم جدا هستند. دسترسی کاربر فقط از نقش‌هایی می‌آید که به حساب او تخصیص یافته‌اند.
- بخش‌ها، داده‌ها و دکمه‌هایی که کاربر مجوزشان را ندارد پنهان می‌شوند. هر خواندن یا تغییر داده همچنین در لایه‌ی مخزن/سرویس کنترل مجوز می‌شود؛ پنهان‌کردن رابط به‌تنهایی کنترل امنیتی نیست.
- تغییر نقش‌ها و مجوزها در عملیات بعدی نشست‌های فعال تازه‌سازی می‌شود. آخرین مدیر سامانه قابل غیرفعال‌سازی یا حذف نیست و نقش داخلی مدیر سامانه قابل ویرایش یا حذف نیست.
- گذرواژه‌ی آشکار حساب فقط هنگام ایجاد یا بازنشانی ارائه می‌شود و در پایگاه داده یا گزارش‌ها ذخیره نمی‌شود. اگر پنجره بسته شد، گذرواژه را بازنشانی کنید تا گذرواژه‌ی موقت تازه‌ای بگیرید.

## نکته‌ی پشتیبانی

SQL Server 2014 برای سازگاری با Windows 7 استفاده می‌شود و پشتیبانی آن در ژوئیه‌ی ۲۰۲۴ پایان یافته است. Windows 7، Windows 8 و Windows 8.1 نیز دیگر به‌روزرسانی امنیتی دریافت نمی‌کنند.
